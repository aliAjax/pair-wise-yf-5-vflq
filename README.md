# 社区药房 · 冷藏疫苗箱借还调度系统

护士提交借箱单，调度员按消毒有效期与容量确认发放；归还登记封条/温度/重量，异常进异常区；复核放行后才能再次借出。全流程留痕。

## 运行

```bash
npm start          # 启动，默认 http://localhost:3000（PORT 环境变量可改）
npm test           # 端到端冒烟测试（29 项断言，内存数据，不写文件）
```

数据持久化在 `data.json`（首次启动自动生成 4 台种子箱，其中 BX-003 消毒已过期用于演示拦截）。可用 `DATA_FILE` 环境变量指定路径。

## 业务规则

- **提交**：护士填姓名、疫苗品种、所需容量(L)、备注 → 借箱单进入「待发放」。
- **发放**：调度员从可用箱中选择确认。服务端校验：箱须为「可用」、消毒在有效期内、容量 ≥ 所需容量。多单争同一箱时，先确认者占用整箱；后来的单收到 409 与当前可用箱列表，页面上改派其他箱再次确认，同一箱不会被重复发出。
- **归还**：记录封条（完好/破损）、温度(℃)、重量(kg)。温度超出 2~8℃ 或封条破损 → 转入「异常区」；正常归还进入「待复核」。
- **复核**：待复核/异常区的箱必须复核后才能再借。结论二选一：
  - **放行** → 箱恢复「可用」，原借单结束；
  - **确认异常·隔离**（必填异常结论）→ 箱进入「隔离中」，不可借，可再次复核放行。
- **留痕**：提交、发放、归还、复核、取消均记录时间与操作人；异常结论、每次交接时间永久保留在「交接与复核记录」。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 全量状态（箱、单、事件、温度常量） |
| POST | `/api/orders` | 提交借箱单 |
| POST | `/api/orders/:id/issue` | 确认发放 `{boxId, actor}`，冲突返回 409 + 可用箱列表 |
| POST | `/api/orders/:id/return` | 归还 `{sealIntact, temperature, weight, actor}` |
| POST | `/api/orders/:id/cancel` | 取消待发放单 |
| POST | `/api/boxes/:id/review` | 复核 `{decision: release\|quarantine, conclusion, actor}` |

## 结构

- `store.js` — 数据与业务规则（单线程同步，检查与占用原子完成）
- `server.js` — 原生 HTTP 服务（API + 静态页），零依赖
- `public/index.html` — 单页操作台（提交/发放/改派/归还/复核，3 秒轮询刷新）
- `test/smoke.test.js` — 端到端测试
